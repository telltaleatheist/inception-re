# .d64: the C64 floppy

The C64 version comes on two Commodore 1541 disks, saved as .d64: the disk's 256-byte
sectors, track by track. A 35-track disk has 683 sectors (174,848 bytes; with the error byte
for each sector after them, 175,531). `src/formats/d64.cpp` lists its files (`read_d64`).
docs/versions.md says which files the game keeps there.

## The layout

- **Sectors per track**: 21 on tracks 1–17, 19 on 18–24, 18 on 25–30, 17 on 31–35. A
  sector's place in the image is the sum of the sectors on the tracks before it, plus its
  number.
- **Track 18, sector 0** is the disk's header and block map. Its first two bytes name the
  directory's first sector (normally track 18, sector 1).
- **The directory** is a chain of sectors (each sector's first two bytes name the next; track
  0 ends it), each with eight 32-byte entries:

  | Bytes | What |
  |---|---|
  | 2 | the file's type: bits 0–2 the kind (1 SEQ, 2 PRG, 3 USR), bit 7 set when the file is closed |
  | 3, 4 | its first track and sector |
  | 5–20 | its name, padded with byte 0xA0 |
  | 30, 31 | its length in sectors, little-endian |

- **A file** is a chain of sectors too: each sector's first two bytes name the next, and the
  other 254 are data. On the last sector the first byte is 0 and the second is the index of
  its last data byte. A program file (PRG) starts with its two-byte load address, which the
  reader keeps.

## What the reader checks

The size, and that the header names track 18; every track and sector is on the disk; no
chain comes back to a sector it has visited. It reads closed SEQ, PRG and USR files and
passes over the rest. A name's bytes outside printable ASCII (and `/`) become `_`.
